# Educational v1 capability matrix

The executable specification is the handwritten parser plus evaluator and tests.
The Lark grammar is a future syntax proposal, not a second runnable interpreter.
This matrix compares the executable subset with the intended language design in
the [README](../README.md#specification), website and
[issue #6](https://github.com/mini-lang/mini-lang/issues/6).

| Capability | Active interpreter | Intended design / Lark draft | v1 decision |
| --- | --- | --- | --- |
| Numbers, bools, strings, unit | Supported; unit is `()` | Draft adds `none` | Keep `()` |
| Variables and blocks | New names local; assignment updates nearest binding | Scoping unspecified | Update nearest existing binding; otherwise create local |
| Functions, lambdas, recursion | Supported, implicit result | Draft also allows `f(x) { ... }` | Keep `f(x) = ...` and `=>`; local parameter bindings |
| `if` / `else if` / `else` | Supported; absent else returns unit | Draft requires `:` for inline bodies | Keep existing inline syntax and braces |
| `while` / `for` | Supported | Grammar declares both | Add boolean while; for over lists, tuples, strings and map keys |
| `break` / `continue` | Supported; validated while parsing | Parsed by draft | Add nearest-loop control; cannot cross function boundary |
| `return` | Function-only; value required | Design includes return from arbitrary blocks | Add function-only explicit return; use `return ()` for unit |
| Lists, tuples, maps | Supported, indexing and bounded slices | Design includes collection methods and sets | Keep free library functions, no sets or methods |
| `a..b` | Eager, end-exclusive integer list | Design includes inclusive, lazy and open-ended ranges | Preserve current bounded semantics |
| Logic | `and`/`or`/`not`, `&&`/`\|\|`/`!`; short-circuit and/or | Design uses single `&`/`\|` | Short-circuit boolean and/or; no bitwise operators |
| Assignment | `=` and identifier `+=` | Draft includes other compound assignments | Keep v1 small: `=` and identifier `+=` |
| Expression boundaries | Whitespace; adjacent calls/indexes | Draft makes newlines significant and uses `:` inline | Preserve handwritten syntax; recommend braces |
| Unicode | Unicode letters and strings | Backlog includes Unicode identifiers and atoms | Keep letters; emoji only in strings |
| Discard names | Underscore names are ordinary variables | Design discards all underscore names | No implicit discards |
| Diagnostics | Located MiniError; CLI stderr and nonzero status | Backlog includes richer diagnostic presentation | Preserve source/line/column through tokens and AST nodes |
| Classes, enums, patterns (`match`, `is`) | Unimplemented | Part of the intended design and grammar | Deferred, explicit errors |
| Membership `in`, destructuring | Unimplemented | Grammar describes both | `in` only in `for name in values`; no patterns |
| Host library | Many existing free functions | Backlog includes further library development | Preserve; only documented examples are v1 guarantees |

These v1 choices describe the current implementation; they do not replace the
full language design. See the [v1 guide](v1-guide.md) for tested examples.

## Loop and scope contract

- `while condition { body }` rechecks a boolean condition before every iteration.
- `for name in values { body }` evaluates values once. It visits list/tuple elements,
  string characters or map keys (strings, in insertion order). Empty unit `()` is
  the empty tuple for iteration. Ranges use the existing list semantics.
- Both loops return `()`, whether empty, completed or broken.
- Each iteration has a fresh local scope. The for variable shadows an outer name
  and never leaks; closures capture that iteration's binding.
- Ordinary assignment updates the nearest existing binding; new names stay in the
  current scope. Function parameters always bind locally, even if an outer name exists.
- `break` and `continue` target the nearest enclosing loop body in the same function.
  Invalid use is rejected even in an unexecuted branch or an uncalled function.
- `return expression` exits the current function through any number of blocks/loops.
  A value is required (`return ()` for unit); it is not a way to exit a top-level block.
